# L. 中抜きリスクと、その防御

> 作成日: 2026-09-17
> 論点: 船宿とフォト事業者が直接つながったら、自分が間に入る意味はあるのか

---

## 0. 結論

### 🔴 懸念は正しい。**純粋な仲介は、必ず中抜きされる。**

これは本事業の**構造的な弱点**であり、
[`A`](./A_船宿ヒアリング質問票.md)〜[`K`](./K_フォトウェディングと古民家.md) で繰り返してきた「提携」戦略の裏側にある最大のリスク。

### ✅ ただし、中抜きされない仲介者も存在する。条件はひとつ。

> ## **「供給」ではなく「需要」を持っていること。**

```
❌ 紹介者 ＝ 既にある需要と供給をつなぐ  →  1回つないだら用済み
⭕ 集客者 ＝ 需要そのものを作り出す      →  切った瞬間に客が消える
```

---

## 1. なぜ中抜きは必ず起きるのか

**これは相手の悪意ではなく、構造の問題。**

| # | 理由 |
|---|---|
| 1 | 両サイドがつながった瞬間、**仲介者の情報優位が消える** |
| 2 | 1回目は必要でも、**2回目以降は不要**になる |
| 3 | 手数料が、双方にとって**「削れるコスト」に見える** |
| 4 | 悪意がなくても「今度は直接どうぞ」と**善意で**起きる |

> 不動産仲介、人材紹介、あらゆるマッチングビジネスが直面してきた問題。
> **「信頼関係があるから大丈夫」は通用しない。** 構造で解く必要がある。

---

## 2. 🚨 特にフォトウェディングは危険

**ご指摘の通り、この商品は中抜きリスクが最も高い。**

| リスク要因 | 内容 |
|---|---|
| **相手が既に集客力を持っている** | ワタベウェディング・デコルテ等は**大手**。客は彼らが持っている |
| **こちらの役割が再現しやすい** | 「船を手配する」だけなら、船宿の番号を知れば誰でもできる |
| **取引が単発** | 結婚前撮りは**一生に一度**。リピートがない＝関係が積み上がらない |

```
あなたが船宿を紹介する
        ↓
フォト事業者「良いロケーションですね。次から直接お願いします」
        ↓
🔴 終わり
```

> ### 🔑 だから、フォトウェディングでは**「紹介する側」になってはいけない。**

---

## 3. ✅ 解決策：立ち位置を逆にする

### ❌ 間違った立ち位置（中抜きされる）
```
フォト事業者（客を持っている）
        ↑ 船宿を紹介する
    あなた ← 手数料をもらう立場
        ↓
     船宿
```

### ⭕ 正しい立ち位置（中抜きされない）
```
        インバウンドの客（自分が集客する）
                ↓
            あなた ＝ 商品の売主
         ↙          ↘
  カメラマン         船宿
（業務委託・発注する側）  （発注する側）
```

> ## **紹介する側ではなく、発注する側になる。**
>
> 「船上フォトウェディング」を**自分のブランドで売り**、
> カメラマンもヘアメイクも**業務委託で手配する。**

### なぜこれで中抜きされないか
- **客は自分のもの**（自社サイト・自分のレビューアカウント経由）
- **カメラマンは代替可能**（1人に依存しない）
- **カメラマンは客を持っていない** → 抜こうにも抜く先がない

### ⚠️ ただし、これには前提がある
> **自分で集客できること。**
>
> → だから [`K`](./K_フォトウェディングと古民家.md) で**「6ヶ月後」**としたのは正しかった。
> **フェーズ1（釣り・観光）でレビューと集客力を作ってから**でないと、
> この立ち位置は取れない。

---

## 4. 🛡 中抜きされないための5つの防御

### ① 需要を持つ（最強・これがすべて）

> **船宿もカメラマンも飲食店も古民家オーナーも、
> 全員が同じ悩みを持っている——「客がいない」。**

彼ら同士が直接つながっても、**集客は誰がやるのか？**
答え：誰もやらない。だから**あなたが必要であり続ける。**

```
❌ 「良い船宿を知っています」      → コネの提供 → 一度きり
⭕ 「毎月30人の外国人客を連れてきます」 → 需要の提供 → 切れない
```

### ② 顧客との関係を自分が持つ
- **予約・決済・問い合わせを自分のチャネルで受ける**
- 客は「船宿」ではなく「**あなたのツアー**」を予約している
- **レビューは自分のアカウントに溜まる**
- → 船宿が直接やろうとしても、**レビューゼロから始まる**

> 💡 **[`H`](./H_事業計画書_固定費ゼロ版.md) の「直販比率を上げる」は、利益率の話であると同時に、
> 中抜き防御の話でもある。**

### ③ 現場で毎回不可欠な労働を提供する
- 引率・安全管理・意思疎通（翻訳機）・撮影・段取り・トラブル対応
- これは**「1回の紹介」ではなく「毎回必要なサービス」**
- **仲介ではなく、労働の提供**になっている限り、外せない

### ④ 供給側を複数束ねる（ポートフォリオ化）
```
船宿1軒と組む   → その1軒に生殺与奪を握られる
船宿10軒を束ねる → 天候・空き状況で選べる＝それ自体が客への価値
```
> ⭐ **1軒が抜けても事業は続く。**
> **束ねていること自体が、真似しにくい価値になる。**
> → [`H`](./H_事業計画書_固定費ゼロ版.md) フェーズ2「ネットワーク化」の本当の意味はこれ。

### ⑤ データを蓄積する（時間が味方になる唯一の資産）
**既に持っている `data/boats.json` と釣果ダッシュボードが効いてくる。**

| 蓄積されるもの | 価値 |
|---|---|
| どの船が・いつ・何を釣っているか | 提案精度 |
| 富士山が見えた日の記録 | 撮影日の判断 |
| 天候別の中止率 | キャンセル予測 |
| 顧客の国籍別の好み | 商品設計 |

> ⭐ **これは時間が経つほど厚くなり、後発が追いつけない。**
> **技術力を持っているあなただけが作れる堀。**

---

## 5. 📊 中抜きされる仲介 vs されない仲介

| | 🔴 中抜きされる | ⭕ されない |
|---|---|---|
| 持っているもの | 情報・コネ | **需要（客）** |
| 役割 | **1回の紹介** | **毎回の労働・段取り** |
| 供給側 | 1社に依存 | **複数を束ねる** |
| 顧客関係 | 供給者が持つ | **自分が持つ** |
| ブランド | 供給者の名前で売る | **自分の名前で売る** |
| 時間経過 | **価値が減衰** | **データが溜まり強くなる** |
| 手数料の見え方 | コスト | **集客費用（払う価値がある）** |

## 6. ⚖️ 契約による防御の限界（正直に）

**「直接取引禁止条項」を入れればいいのでは？ → 効果は限定的。**

| 論点 | 現実 |
|---|---|
| 紹介手数料契約・直接取引制限は実務上存在する | ⭕ 抑止力にはなる |
| 零細事業者相手に法的拘束を効かせられるか | 🔴 **訴訟コストの方が高い** |
| 立証できるか | 🔴 「独自に知り合った」と言われたら困難 |
| 関係性への影響 | 🔴 **契約で縛ろうとすると信頼を失う** |

> ### 🔑 **契約は「抑止力」であって「防御」ではない。**
> **構造で守れないものを、契約で守ろうとしてはいけない。**

✅ **やるべきは最低限：**
- 紹介した案件の手数料について、**書面で合意しておく**（シンプルに）
- ただし**それを頼りにした事業設計にしない**

## 7. 🎯 だから、こう設計する

### 大原則
> ## **「仲介」で始めて、「需要の保有者」で終わる。**

```
フェーズ1  自分がガイドとして客を連れて行く
          （＝仲介ではなく、労働の提供。中抜きされる余地がない）
              ↓
フェーズ2  レビューと直販サイトで「客を持つ」状態を作る
          複数の船宿・カメラマン・店を束ねる
              ↓
フェーズ3  自分が発注する側になる
          （供給側は代替可能。客だけは自分のもの）
```

### 🚫 やってはいけないこと
- 🚫 **「紹介だけ」で手数料を取るモデルに寄せない**（最も中抜きされやすい）
- 🚫 **1つの供給者に依存しない**
- 🚫 **供給者のブランドで売らない**（「〇〇丸のツアー」ではなく「自分の屋号のツアー」）
- 🚫 **客の連絡先を供給者に渡さない**（現場で自然に交換されるのは防げないが、積極的に渡さない）

### ⭕ やるべきこと
- ⭕ **自分の屋号・ブランドで売る**
- ⭕ **直販比率を早く上げる**（利益率＋中抜き防御の二重の意味）
- ⭕ **レビューを自分の資産として積む**
- ⭕ **供給側を10軒束ねる**
- ⭕ **データを蓄積する**（技術力が最も効く領域）

## 8. 💡 発想の転換：中抜きされる前提で設計する

**「絶対に中抜きされない方法」を探すのは不毛。必ず一部は抜かれる。**

> ### 正しい問いは：
> ## **「中抜きされても事業が死なない構造になっているか？」**

| 問い | 答えられる状態にする |
|---|---|
| 船宿1軒が抜けても事業は続くか？ | **10軒束ねていればYES** |
| カメラマンが抜けても続くか？ | **客を自分が持っていればYES** |
| 抜けた相手は、自分の客を奪えるか？ | **直販・レビューが自分のものならNO** |

> ⭐ **供給者は代替可能にしておく。需要（客）だけは絶対に手放さない。**
> **これが唯一の答え。**

## 9. 各提携先ごとの中抜きリスク評価

| 提携先 | リスク | 防御 |
|---|---|---|
| **船宿** | 🟡 中 | 客は外国人。**船宿が自力で集客するのは言語的に困難**。<br>10軒束ねれば1軒抜けても問題ない |
| **飲食店（釣果調理・貸切）** | 🟢 低 | 送客するだけ。**店が自力で外国人を集めるのは困難** |
| **和装レンタル店** | 🟢 低 | 同上。かつ店側は既存業務の追加収入なので歓迎される |
| **🔴 フォト事業者** | **🔴 高** | **相手が集客力を持っている。**<br>→ **紹介者ではなく発注者になる**（第3章） |
| 古民家オーナー | 🟢 低 | オーナーの悩みは稼働率＝集客。**送客側が強い** |

> 🔑 **リスクが高いのはフォトウェディングだけ。**
> **他は「相手が自力で外国人客を集められない」ため、構造的に安全。**
>
> ⭐ **そしてそれを可能にしているのが、[`J`](./J_言語制約と船の取得ルート.md) で課題として挙げた「言語」。**
> **あなたにとって弱点だった言語は、供給者にとってはもっと大きな壁であり、
> それがあなたの参入障壁になっている。**

|---|---|
