# 副業ビジネス立案ドラフト

> 新規事業立ち上げの検討メモ。仮説→検証→意思決定を早く回すための作業ドキュメント。
> 最終更新: 2026-09-17

---

## 0. 進め方（結論を先に）

大きく育てる（本業化を狙う）ほど、**「作る前に売れるか確かめる」**ことが成功率を左右する。
このプロジェクトは次の順で回す。

```
① 創業者の強み整理  →  ② 事業テーマ選定（評価軸でスコアリング）
     →  ③ 最有力1本に絞る  →  ④ 90日で検証（作らずに需要確認）
     →  ⑤ 続ける/やめる/変える の意思決定
```

---

## 1. 創業者プロファイル（前提）

| 要素 | 内容 |
|---|---|
| 技術力 | Python / Web / データ / 自動化（一人でプロダクト構築が可能） |
| AI・データ | LLM・データ分析を実装／活用できる |
| **業界知見・人脈** | ★最重要・**要記入** → どの業界か？（下の「2.」で確定） |
| 投下時間 | 週15時間以上 |
| 初期資金 | 月5万円以上も可 |
| ゴール | 将来の本業化・大きな成長（スケール志向） |
| 好みの事業モデル | EC・物販・仕入販売 / マッチング・代行・サービス |

### この組み合わせが示す「勝ち筋」
技術者でありながら実業（EC・物販／マッチング）を選ぶ、という点が鍵。
技術・AIを**プロダクト本体**ではなく、**「仕入・出品・運用・需給マッチングの自動化エンジン」**として使う。
→ 非技術者の事業者に対し「運用の速さ・精度・コスト」で明確に勝てる。

## 4. 90日検証プラン（作らずに需要を確かめる）

| 週 | やること | 完了の判断基準 |
|---|---|---|
| W1-2 | 顧客インタビュー5〜10件（業界の知人から） | 「困っている」が具体的に言語化できる |
| W3-4 | 最小の売り物を定義（何を・いくらで・誰に） | 価格と提供内容が1枚で説明できる |
| W5-6 | LP or 手動オファーで「事前予約／申込」を募る | 反応（申込・問い合わせ）が出る |
| W7-10 | **手動で**最初の数件を提供（自動化しない） | 有料で1件以上成約 |
| W11-12 | 再現性の確認→自動化する部分を特定 | 2件目以降を回す型ができる |

> 原則: **最初は自動化しない**。手作業で売れることを確認してから、
> 儲かる／回らない部分だけをPython・AIで自動化する。

### 検証コスト目安（月5万円以内）
- ドメイン・LP・決済（Stripe等）… 数千円/月
- 広告テスト（少額のSNS/検索広告）… 1〜3万円
- ツール・API … 数千円

## 5. リスクと撤退ライン
- **時間**: 週15hを3か月＝約180h。ここで「有料成約ゼロ」なら案を変える。
- **資金**: 検証フェーズは累計15万円を上限とする。
- **法規制**: 業界により許認可・古物商・特商法表記等が必要。テーマ確定後に確認。
